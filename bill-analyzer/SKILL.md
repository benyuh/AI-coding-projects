# Skill: Finance Bill Analyzer

## 触发条件 | Trigger

当用户提到以下任意场景时，自动加载此 Skill：
- 有银行账单 Excel / CSV / TXT 需要整理或分析
- 想做年度/月度消费复盘
- 提到"账单梳理"、"财务分析"、"消费统计"

## 工作流概览

5 个阶段，每阶段结束后**停下等用户确认**，不一口气跑完。

```
阶段 1：数据探查 + 规律预扫        → 01_overview.md
阶段 2：清洗与抹平（退款/转账）    → 02_cleaned.csv + 02_cleaning_report.md
阶段 3：分类补全（行为规律驱动）   → 03_classified.csv + 03_ambiguous.md
阶段 4：分析框架确认               → 框架草图（无文件输出，等确认）
阶段 5：最终交付                   → report.html + scripts/ + README.md
```

---

## 启动交互

Claude Code 启动后，引导用户：

1. **拖入文件**：让用户把 Excel 拖进终端窗口，从路径读取，不要提前假设位置
2. **确认工作目录**：默认在文件同级建 `finance-YYYY/` 目录，等用户确认
3. **原始文件只读**：所有输出写入 `processed/` 和 `output/` 子目录

第一次交互示例：
```
你：[把 Excel 拖进终端，显示为 /Users/xxx/Downloads/2025账单.xlsx]
    请开始阶段 1
我：[读取路径，读取所有 sheet，确认工作目录]
```

## 字段说明

Excel 主表的关键字段（字段名可能因用户不同而有差异，读取后自动识别）：

| 字段 | 说明 |
|------|------|
| 交易时间 | 原始时间字符串 |
| 交易账户 | 银行卡/支付宝/微信等 |
| 备注 | 商户名或交易说明（可能有多列，如备注0-7） |
| 交易方式/分类 | 已有标签（可能部分为空） |
| 金额 | 原始金额 |
| 金额CNY | 换算后人民币金额 |
| 收/支 | 方向标识 |
| 交易状态 | 成功/退款/冻结等 |

## 阶段 1：数据探查 + 规律预扫

### 任务
1. 读取所有 sheet，找到用户的**二级分类体系** sheet
2. 概览主表（行数、时间跨度、账户列表、币种分布）
3. 统计已有分类覆盖率（多少笔有标签、多少笔为空）
4. **预扫行为规律**（见"行为规律识别框架"章节）
5. 发现明显异常（极大金额、重复行、乱码等）

### 输出：`processed/01_overview.md`

```markdown
## 数据概览
- 总行数：N 笔，时间跨度：YYYY-MM ~ YYYY-MM
- 账户：[列表]
- 已分类：N 笔（X%），未分类：N 笔

## 你的分类体系
[从 sheet 中提取的完整二级分类树]

## 发现的行为规律
[规律清单，每条带样本，见格式规范]

## 建议补充的分类（如有）
[仅在现有体系无法覆盖时提出，需用户确认]

## 异常样本
[极大金额、重复行等]
```

**⏸ 停下等用户确认后再进入阶段 2**

---

## 阶段 2：清洗与抹平

### 识别目标
- 购物退款（原消费 + 退款配对）
- 旅游/服务退款
- 内部账户转账
- 信用卡还款

### 内部转账识别思路（参考 `reference/transfer_patterns.md`）

不要逐笔问，先识别**转账模式**再整体确认：
- 同日、两账户、金额相等、方向相反
- 备注含"还款/转入/转出/信用卡"等关键词
- 固定日期的规律性转账（工资卡→理财、信用卡还款日等）
- 账单日前后大额转入

把识别到的**模式总结**给用户看（如"发现 3 种转账模式：A→B 日常调度、C→D 信用卡还款、E→F 理财定投"），不要一笔笔列出来确认。

### 汇报格式：事件簇

```
【事件簇 #N】描述（如：2025-10 大额退款潮）
  涉及账户：招行信用卡、支付宝
  原始交易（共 N 笔）：
    YYYY-MM-DD  账户  金额  完整备注
    ...
  配对逻辑：[为什么这几笔是一组]
  置信度：高/中/低
  存疑：[有问题的笔，金额对不上、时间差过大等]
  建议：[直接抹平 / 请用户确认]
```

- 金额小且有问题的直接剔除，但列清单给用户过一眼
- 大额或存疑的单独列出请用户判断

### 输出
- `processed/02_cleaned.csv`
- `processed/02_cleaning_report.md`

**⏸ 停下等用户确认**

---

## 阶段 3：分类补全（行为规律驱动）

### 核心原则

**先找规律，再批量分类**。不要逐笔判断。

用阶段 1 发现的规律 + 商户信息 + 用户的分类体系，给未分类项归类。

### 汇报格式：规律簇

```
【规律簇 A】名称（如：工作日早通勤）
  样本（3-5 条有代表性的）：
    YYYY-MM-DD  HH:MM  账户  金额  备注
    ...
  识别依据：[时间段 + 商户特征 + 金额范围]
  推测分类：交通-通勤 / 餐饮-早餐
  置信度：高/中/低
  涉及笔数：N 笔，总金额：X 元
  建议：批量归入 "[分类名]"
  需要确认？[是/否]
```

置信度高的可以直接批量操作，中/低的等用户确认。

### 输出
- `processed/03_classified.csv`
- `processed/03_ambiguous.md`（中低置信度、无法归类的条目）

**⏸ 停下等用户确认**

## 阶段 4：分析框架确认

列出准备计算的内容，等用户确认再执行：

- **指标清单**：月均支出、各分类占比、同比/环比趋势等
- **财务健康度评估维度**：储蓄率、消费结构、大额异常等
- **2026 预算推导逻辑**：基于历史均值 + 已知变化（如搬家、换工作）
- **报告页面结构草图**：首页概览、月度明细、分类钻取、预算建议

**⏸ 停下等用户确认**

## 行为规律识别框架

在阶段 1 预扫时，主动检测以下维度：

| 维度 | 识别示例 |
|------|------|
| **时间段** | 23:00–02:00 小额 + 生鲜商户 → 深夜买菜 |
| **星期** | 周六日白天 + 餐饮 → 周末聚餐（≠ 工作餐） |
| **通勤时段** | 工作日 07:30–09:00 或 17:30–19:30 + 交通 → 通勤 |
| **固定金额** | 每月固定日 + 固定金额 → 订阅/房租/贷款 |
| **金额分布** | 单笔 >300 + 周末 + 打车 → 聚会/活动出行 |
| **商户聚类** | 连续 N 天在同一城市/区域消费 → 出差/旅游 |
| **账户专用** | 某卡几乎只用于某类消费 → 可作为分类信号 |

---

## 核心原则

1. **每阶段停下等用户确认**，不一口气跑完
2. **抓大放小**：金额小且有问题的直接忽略，列清单即可
3. **不分析**：内部转账、信用卡还款、已退款订单（全部抹平，不计入消费）
4. **原始内容要贴**：阶段 2、3 汇报时把原始交易完整贴出（时间、账户、金额、备注）
5. **先找规律再分类**，不要逐笔判断
6. **分类体系以用户为主**，必要时补充但须明确告知
